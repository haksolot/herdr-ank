constraint: |
  Le plugin cible linux, macos et windows, et le manifeste le déclare. Il reste un seul binaire Rust, herdr-ank (herdr-ank.exe sur Windows), et toute entrée du manifeste autre que [[build]] invoque ./bin/herdr-ank ou ank tui à travers lui. [[build]] porte deux scripts et pas plus : install.sh (POSIX sh, platforms linux et macos) et install.ps1 (Windows PowerShell 5.1, platforms windows), de même contrat : lire la version du manifeste, télécharger l'archive de la plateforme depuis la release GitHub v<version>, vérifier sa somme dans SHA256SUMS, poser le binaire dans ./bin/, cargo build --release en repli seulement si cargo est présent, sinon sortir 1 en nommant ce qui manque. Les cibles publiées par le workflow de release sont x86_64-unknown-linux-musl, aarch64-unknown-linux-musl, x86_64-apple-darwin, aarch64-apple-darwin et x86_64-pc-windows-msvc (archive .zip), et le workflow refuse un tag dont la version diverge de Cargo.toml ou du manifeste. Sur Windows, HERDR_SOCKET_PATH nomme un named pipe, ouvert en lecture-écriture comme un fichier, et le dialogue NDJSON est le même ; toute API propre à un système vit derrière cfg(unix) ou cfg(windows) avec son pendant, jamais sans. Une clause Windows d'un critère est prouvée par le job Windows du workflow CI sur une branche poussée, jamais déclarée sur parole.

Remplace ADR-7aab39e2dbd8 sur la plateforme ; sa décision de distribution par
release GitHub et script d'amorçage tient, et est reprise ici mot pour mot.

Le 2026-09-25, l'utilisateur a demandé Windows. Le relevé du code donne
quatre points Unix : `UnixStream` pour `events.subscribe`, `exec` du TUI,
`HOME` pour la racine des worktrees, et les faux binaires des tests écrits en
sh. herdr lui-même tourne sur Windows et y expose son API par named pipe,
`ank` y livre un binaire, et le manifeste sait porter `platforms` par entrée :
rien côté hôte n'empêche le plugin d'y vivre.

Ce qui manque est une machine pour mesurer. Le choix est de faire de la CI
GitHub cette machine : un workflow qui exécute tests, clippy et fmt sur
ubuntu, macos et windows, et la règle qu'une clause Windows n'est close que
par ce job. C'est plus lent qu'un poste local et c'est la seule preuve
disponible ; un agent pousse sa branche de tâche pour l'obtenir.

Windows sur ARM n'est pas publié : aucun runner GitHub hébergé ne le couvre
en natif au moment de la décision, et une cible non mesurée ne serait qu'un
nom dans une liste.
