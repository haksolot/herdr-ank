  herdr-plugin.toml déclare [[actions]] id = "land", titre « Land a task », contexte workspace, commande herdr-ank land. herdr-ank land ouvre la popup pick en mode land : elle ne liste que les tâches done du corpus du workspace dont la branche task/<id court> existe et n'est pas ancêtre de la branche par défaut, filtrables au clavier. Sur un choix, le module land (TASK-a4cfb858a246) s'exécute ; un refus envoie une notification qui nomme la cause et la commande qui la lève, et rien n'est nettoyé. Sur Landed, dans cet ordre et chacun seulement si sa clé [land] est true : herdr tab close de chaque onglet dont une pane a son cwd sous le worktree ; herdr worktree remove du worktree ; git branch -d task/<id court> ; git push origin --delete task/<id court> seulement si ls-remote la trouve sur origin. Puis une notification « TASK-xxxx landée sur <défaut> ». Un échec de nettoyage n'annule pas le landing : il est notifié et les étapes suivantes s'exécutent. Le client herdr gagne tab_list, tab_close et worktree_remove, testés dans tests/herdr_client.rs. tests/land_action.rs vérifie sur le binaire herdr factice et de vrais dépôts git temporaires : l'ordre exact des appels, chaque clé à false qui saute son étape, un refus qui n'appelle aucun nettoyage. Une session herdr réelle est mesurée et consignée par ank log : une tâche lancée par Work a task puis landée ne laisse ni onglet, ni worktree, ni branche locale ou distante. Le README décrit l'action dans « What it does ». CI verte sur les trois OS.
