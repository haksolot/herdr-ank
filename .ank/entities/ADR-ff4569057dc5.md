Landing une tâche, c'est le rituel qu'un dépôt ank impose à la fin de chaque
claim : la branche `task/<id court>` est rebasée sur la branche par défaut, puis
la branche par défaut avance en fast-forward dans l'arbre d'intégration. ank ne
le fait pas (il ne commit que `accept`), herdr ne le fait pas (il crée et
supprime des worktrees, il ne fusionne rien). Reste git.

Deux voies ont été pesées. Confier le landing à l'agent par `agent prompt` évite
git dans le plugin, mais le résultat n'est pas vérifiable par le plugin et
dépend de l'AGENTS.md de chaque dépôt. Lancer git depuis le plugin est
déterministe, testable contre un dépôt temporaire, et identique sur les trois
OS (git est déjà un prérequis de herdr worktree).

La frontière est celle d'ADR-357c pour herdr et d'ADR-3cd1 pour ank : une CLI,
un module, une liste fermée d'opérations. Tout ce qui déplace la branche par
défaut sur un remote (push de main, tag, release) reste un geste humain.

Le landing est un geste explicite : une action du menu, jamais le daemon. La CI
n'est pas consultée en v1 ; la déclencher reste à l'humain qui lance l'action.
