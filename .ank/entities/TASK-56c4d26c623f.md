Deux mesures d'ank-2 sur le daemon livré (TASK-91a1), consignées dans son
rapport du 2026-09-25 :

- `ank context` passe en mode exécution dès que l'identité qui l'appelle tient
  un claim. Le daemon tourne sans `ANK_AGENT`, donc sous l'identité de repli
  `<user>@<host>`, celle qu'un humain ou un agent sans plugin porte aussi.
  Quand elle tient une tâche, la file rend 0 et `ank_queue` ment.
- Le critère de 91a1 demandait `ank watch --where`, que le client ne proposait
  pas ; le daemon l'a lancé lui-même, contre la règle du corps de TASK-dadb :
  rien hors `src/ank` ne spawne `ank`.

L'identité `<user>@<host>/herdr-ank` suit la forme d'ADR-fa8b6a103597 avec
un suffixe qu'aucun agent herdr ne peut porter par l'action `work`, dont les
noms commencent par `ank-`.
