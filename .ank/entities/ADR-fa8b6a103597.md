  Quand le plugin démarre un agent, la pane reçoit ANK_AGENT=<user>@<host>/<nom de l'agent herdr>, où <user>@<host> est l'identité de repli qu'ank calcule lui-même. ank arbitre les claims par identité : `ANK_AGENT`, sinon `<user>@<hostname>`.
Deux sessions dans un même arbre sans `ANK_AGENT` sont un seul agent pour les
refs, mode dégradé que le skill ank nomme comme tel. Le plugin est le bon
endroit pour poser l'identité, puisqu'il démarre l'agent et connaît la pane.

Trois formes ont été pesées le 2026-09-25 :

- **le nom d'agent herdr** (retenu) : renommable par `herdr agent rename`,
  stable pour la durée d'une tâche, lisible par un humain dans la sidebar ;
- **l'id de pane** (`w1:p3`) : mapping trivial, mais l'id change quand la
  session est restaurée, et le claim devient orphelin ;
- **la branche du worktree** (`task/<id>`) : cohérent avec « un agent, un
  arbre », mais deux agents dans l'arbre partagent le claim et l'identité ne
  dit plus qui est là.

Le préfixe `<user>@<host>/` garde l'identité unique entre machines quand un
corpus est partagé par un remote, et laisse un lecteur reconnaître d'où vient
un claim sans plugin.
